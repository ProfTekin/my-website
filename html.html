REFERENCE 01 / HTML

HTML: give content structure.

Start with meaning. Build clear pages, connect them, and make your content accessible.

The document: head and body

HTML describes content and its structure. Elements tell the browser what each part means. Save this complete reference as index.html.

Code
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Alpine Coffee | Home</title>
  <link rel="stylesheet" href="style.css">
  <script src="script.js" defer></script>
</head>
<body>
  <header><h1>Alpine Coffee</h1></header>
  <main><p>A fictional café in Innsbruck.</p></main>
  <footer><p>School learning example.</p></footer>
</body>
</html>

The doctype selects standards mode; it is not an HTML element. html is the root, with a language for assistive tools. head contains metadata, the browser-tab title and file links. body contains visible page content. UTF-8 supports international characters. The viewport lets responsive layouts use device width. defer runs an external script after parsing.

Try it yourself

Change the browser-tab title and visible heading. Explain why they are separate.

Elements, attributes and nesting

Most elements have an opening tag, content and a closing tag. Attributes supply extra information inside the opening tag.

Code
<p>Try our <strong>seasonal coffee</strong>.</p>
<a href="menu.html" class="button">Read the menu</a>
<img src="images/coffee.svg" alt="A cup of coffee">

The complete <a>…</a> is an element. href is an attribute and menu.html its value. Close the inner element before the outer one. Images are void elements: they have no closing tag.

Headings, paragraphs and text

Use headings to communicate hierarchy. Start with a clear page heading, then use h2 for major sections and h3 for subsections.

Code
<h1>Our café</h1>
<h2>Our story</h2>
<p>We started with a love of <strong>good coffee</strong>.</p>
<p>Try our <em>seasonal</em> special.<br>Served warm.</p>

Use strong for importance and em for emphasis. Use CSS for visual styling rather than choosing headings by size. Paragraphs create text blocks; br is a line break, not a spacing tool.

Links, navigation and multiple pages

Each HTML file is a separate page. Links connect the pages. index.html is the conventional entry page when a web server opens a folder.

Code
<nav aria-label="Main navigation">
  <a href="index.html">Home</a>
  <a href="about.html">About</a>
  <a href="menu.html">Menu</a>
  <a href="contact.html">Contact</a>
</nav>
<a href="#opening-hours">Jump to opening hours</a>
<section id="opening-hours"><h2>Opening hours</h2></section>

The href gives a destination. A hash links to an ID on the page; contact.html#opening-hours links to a section on another page. Use descriptive link text. Use links to navigate and buttons to perform actions.

Images and alternative text

An image needs a correct path and an appropriate text alternative. Describe its purpose in context.

Code
<img src="images/coffee.svg"
     alt="Illustration of a steaming cup of coffee"
     width="400" height="300">
<img src="images/decorative-line.svg" alt="">

Use empty alt="" for purely decorative images. Do not omit alt or use a filename as a description. Width and height reserve space. Use CSS max-width: 100%; height: auto; for responsive images. The second line illustrates a decorative asset; create that file before using it.

Lists, divs and spans

Use lists for collections. Use div or span only when a more meaningful element does not fit.

Code
<ul>
  <li>Espresso</li>
  <li>Tea</li>
</ul>
<ol><li>Choose a drink.</li><li>Visit the counter.</li></ol>
<div class="product-card">
  <p>Espresso <span class="price">€3</span></p>
</div>

ul is unordered; ol has an order. Each item is an li. A div is a generic block container; span is a generic inline container. Neither explains meaning by itself.

Semantic page structure

Semantic elements describe the role of content and make your document easier to navigate and maintain.

Code
<header><h1>Alpine Coffee</h1></header>
<nav aria-label="Main"><a href="index.html">Home</a></nav>
<main>
  <section aria-labelledby="specials-title">
    <h2 id="specials-title">Our specials</h2>
    <article><h3>Seasonal blend</h3><p>A rich roast.</p></article>
  </section>
</main>
<footer><p>Fictional school example.</p></footer>

Use one main landmark for the page’s main content. Header introduces, nav groups navigation, section groups a topic, article is self-contained content, and footer closes a page or section.

IDs, classes and buttons

An ID uniquely identifies one element in a document. A class groups elements that share a style or behavior.

Code
<h2 id="welcome" class="section-title">Welcome</h2>
<h2 class="section-title">Our menu</h2>
<button type="button" id="welcome-button">Say hello</button>

Do not repeat an ID on the same page. Classes may be reused, and one element may have several classes. The button needs JavaScript to change the heading: see getElementById and events. See also CSS selectors.

Tables for structured data

Use tables for information with row and column relationships, not for page layout.

Code
<table>
  <caption>Illustrative opening hours</caption>
  <thead><tr><th scope="col">Day</th><th scope="col">Hours</th></tr></thead>
  <tbody>
    <tr><th scope="row">Monday</th><td>08:00–17:00</td></tr>
    <tr><th scope="row">Sunday</th><td>Closed</td></tr>
  </tbody>
</table>

Caption names the table; th identifies headers; scope states whether a header describes a row or column. td contains ordinary data.

Forms, inputs and labels

A label explains an input. Match its for attribute to the input’s ID. Browser validation helps users enter suitable values.

Code
<form id="demo-form">
  <label for="guest-email">Email (demonstration only)</label>
  <input id="guest-email" type="email" required>
  <button type="submit">Check format</button>
</form>
<p id="feedback" role="status"></p>

Use suitable types such as text, email or number; select offers choices and textarea accepts longer text. A placeholder is not a replacement for a label. A form does not send email or store data by itself. Add the demonstration handler in form validation. Do not collect real visitor information in your prototype.

File paths and external files

A relative path starts from the file that contains it. Keep names short, lowercase and consistent.

Code
<!-- In index.html at the website root -->
<link rel="stylesheet" href="style.css">
<script src="script.js" defer></script>
<img src="images/coffee.svg" alt="Coffee illustration">
<a href="about.html">About</a>
<!-- In a page one folder deeper -->
<a href="../index.html">Home</a>

../ goes up one folder. HTML paths resolve relative to the HTML page; CSS url() paths resolve relative to the stylesheet. Avoid paths starting with / for this portable project. Filenames can be case-sensitive when hosted. Keep index.html at the publication root.

Try it yourself

Common HTML mistakes

SymptomWhat to inspect
Text unexpectedly boldLook for a missing closing strong tag.
Missing imageCheck src, extension, capitalization and whether the file is present.
Broken navigationCheck href and the exact name of the other HTML file.
Unexpected page structureInspect invalid nesting; do not put a div inside a p.
Controls hard to useAdd labels, use real buttons and provide meaningful link text.

Use the browser Elements panel to compare the parsed document with your source. Browsers repair some invalid markup, which can hide your mistake.
