03.1 / WHO SERVES WHOM?

Two ways to work together.

A network architecture describes the roles devices take. It is different from a topology, which describes their connections.

A device can be a client for one service and a server for another. Peer-to-peer systems can still use central services for discovery. Architecture does not determine whether a network uses Wi-Fi or cables.
03.2 / DEFENCE IN DEPTH

No single shield is enough.

Security protects confidentiality, integrity and availability. Combine technical controls with updates, strong authentication, backups and careful user behaviour.

01

Encryption

Transforms readable data into ciphertext using a key. Properly implemented encryption protects confidentiality; authenticated encryption also detects tampering.

Use HTTPS/TLS for web traffic. Wi-Fi encryption protects the wireless link, not automatically the entire journey. Encryption does not stop phishing or a compromised endpoint.

02

Firewall

Allows or blocks traffic according to rules, such as source, destination, port and connection state. Firewalls can run on devices or at network boundaries.

A firewall reduces unwanted access. Allowed traffic can still be malicious; a firewall does not replace software updates or authentication.

03

VLAN

A virtual LAN divides a switched network into separate logical broadcast domains, even when devices share physical switches.

Put students, staff and guests in separate VLANs. Traffic between VLANs requires routing; firewall or access-control rules decide what is permitted. VLANs do not encrypt data.

INSPECT / SCHOOL SEGMENTATION

Same building. Separate zones.

Guest devices need internet access, not access to staff files. Student devices may use the project NAS, while staff records stay in a separate zone.

Segmentation limits the reach of a problem. Secure management, correct configuration and enforced inter-VLAN rules still matter.

BRING IT ALL TOGETHER / 15–20 MINUTES

Design the next
school network.

A school needs to connect 24 PCs, staff laptops, guest phones and a shared project NAS. It also needs internet access and protection for staff files.

  1. Draw a topology and label the switch, router and NAS. Explain your choice.
  2. Choose connection types for PCs, laptops and phones. Justify one trade-off.
  3. Choose operating systems and a client–server or peer-to-peer approach.
  4. Trace a file transfer using FTP, TCP and IP. Explain why classic FTP is unsuitable for confidential data.
  5. Identify the OSI layers responsible for signals, local frames, routing and reliable transport.
  6. Design VLANs, firewall rules and encryption. Explain one risk these do not solve.

Compare with one possible solution

Use a switched star with Ethernet for the 24 PCs and NAS; use access points for staff and guest Wi-Fi. A router/firewall provides internet access and controls routing between student, staff and guest VLANs. Use a server or NAS for central accounts and files, with permissions and separate backups. Windows, Linux and macOS clients can communicate through shared protocols.

Permit students to use the project NAS and guests to reach the internet, while denying guests access to staff resources. Use authenticated encrypted file transfer such as SFTP or HTTPS. In a classic FTP example, FTP defines file commands, TCP provides an ordered byte stream and IP handles addressing/routing. OSI layers 1, 2, 3 and 4 correspond to signals, frames, packets and transport respectively. Phishing, stolen credentials and a central switch failure still need attention.
